# DDoSGuard

Paper 1.20.x용 접속·요청 과부하 방어 플러그인입니다. **영구 밴, 임시 밴, IP 밴을 사용하지 않습니다.** 접속 처리 예산을 초과하면 연결을 거절하고, 플레이 중 반복적인 과도한 요청은 취소한 뒤 지속될 경우 해당 유저를 추방합니다.

## 다운로드 및 설치

1. [DDoSGuard-1.0.0.jar](dist/DDoSGuard-1.0.0.jar)를 서버의 `plugins/`에 넣습니다.
2. 초기 로그인 및 PLAY 패킷 단계 보호도 사용하려면 [ProtocolLib 5.3.0](https://github.com/dmulloy2/ProtocolLib/releases/tag/5.3.0)을 함께 설치합니다. DDoSGuard JAR에 ProtocolLib는 포함되어 있지 않습니다.
3. 서버를 재시작합니다. 플러그인 관리자에 의한 hot-load/hot-unload는 지원하지 않습니다.
4. 콘솔에서 `ddosguard status`를 실행하여 모드와 ProtocolLib 연결 여부를 확인합니다.
5. `plugins/DDoSGuard/config.yml`을 서버 용량과 정상 트래픽에 맞게 조정합니다. 설정 후 `ddosguard reload`로 적용합니다.

대상: Paper 1.20 계열, Java Edition. 플러그인 바이트코드는 Java 17입니다. Paper 1.20.5/1.20.6 서버 자체는 Java 21로 실행해야 합니다. Spigot, Folia, Bedrock 전용 서버는 지원 대상으로 검증하지 않았습니다.

기본 모드는 `enforce`입니다. 실제 유저가 있는 서버에 처음 도입할 때 `ddosguard mode observe`로 정상 요청량을 측정한 후 제한을 조정할 수 있습니다. `observe`는 차단·취소·추방을 하지 않습니다.

## 구현된 기능

| 기능 | Paper 단독 | ProtocolLib 함께 설치 |
|---|---|---|
| 전역 로그인 처리량 제한 | AsyncPlayerPreLogin 시점 | LOGIN START 시점 |
| 미완료 로그인 수 상한·제한 시간·닫힌 연결 정리 | 지원 안 함 | 지원 |
| 명령어·자동완성·채팅 반복 요청 제한 | 지원 | 지원 |
| 책 편집·인벤토리 클릭·아이템 버리기 제한 | 지원 | 지원 |
| CUSTOM_PAYLOAD 반복 요청 제한 | 지원 안 함 | 지원 |
| 전체 PLAY 패킷의 지속적인 과다 전송 감지 | 지원 안 함 | 지원 |
| 서버 목록 핑 별도 예산 | 지원 | 지원 |
| 자동 보호 상태·회복 지연 | 지원 | 지원 |
| 관찰 모드·상태·최근 진단·설정 재적용 | 지원 | 지원 |

서버 목록 핑 초과 시에는 응답을 취소합니다. 전체 PLAY 패킷은 서명된 채팅, 이동, KeepAlive 등을 손상시키지 않도록 일부를 임의로 버리지 않습니다. 지속적인 초과가 추방 기준까지 도달한 경우에만 연결을 종료합니다. CUSTOM_PAYLOAD와 Paper 이벤트는 초과 요청을 취소하여 뒤의 처리를 줄입니다.

## 추방 안내

이 플러그인이 내리는 접속 거절과 추방은 다음 공통 문구를 사용합니다. `kick-message`에서 수정할 수 있습니다.

> 서버 보호를 위해 연결이 일시적으로 종료되었습니다.<br>
> 잠시 후 다시 접속해 주세요.<br>
> 정상 이용 중 문제가 반복된다면 디스코드에서 문의 티켓을 열어주세요.

재접속 금지 기록을 남기지 않습니다. 다만 재접속 시에도 당시의 처리량 제한은 적용됩니다. 다른 플러그인의 추방, 정품 인증 실패, 네트워크 단절, 프로토콜을 해석할 수 없는 초기 오류의 문구를 덮어쓰지는 않습니다. 디스코드 메시지나 티켓을 자동 전송하지 않습니다.

Paper의 `SPAM`, `TOO_MANY_PENDING_CHATS` 사유는 `enforce` 모드에서 같은 안내로 바꿉니다. `native-spam-kick-message: false`로 끌 수 있습니다. 다른 서버 코어 사유나 수동 추방은 변경하지 않습니다.

## 정상 유저 보호 정책

- IP별 밴/접속 금지, 국가·VPN 차단, 닉네임·미인증 UUID 신뢰 목록을 사용하지 않습니다.
- 플레이 제한 상태는 개별 접속 세션에만 저장합니다. 같은 IP의 다른 유저에게 위반 횟수가 전파되지 않습니다.
- 토큰 버킷의 여유량으로 순간적인 요청 몰림을 허용합니다. 플레이 중 최초 초과만으로 즉시 추방하지 않습니다.
- 기본값은 10초 집계 기간 중 초과 30회 이상, 최초 초과 후 최소 3초 경과를 함께 요구합니다. 로그인 입장 예산은 별도로 즉시 적용됩니다.
- 공격 상태에서는 신규 로그인 처리량만 낮춥니다. 기존 플레이어를 일괄 추방하지 않습니다.
- 진단 기록은 개수 상한을 갖습니다. 접속 처리 중 외부 API, DB, DNS, 디스크 저장을 동기 호출하지 않습니다.
- 추방 작업은 크기가 제한된 큐에서 메인 스레드로 처리합니다. 오래된 세션의 작업이 재접속한 유저를 추방하지 않게 세션을 재확인합니다.
- 잘못된 설정을 reload하면 기존 정상 설정을 유지합니다. 정상 reload는 일시적인 카운터·세션 제한 이력을 초기화합니다.

**정상 유저 오차단 0%는 보장하지 않습니다.** 정상 유저와 같은 행동을 하는 봇, 회선/서버 용량을 넘는 공격에서는 정상 신규 접속도 지연되거나 거절될 수 있습니다. PC방 동시 접속, 모드, Geyser/Floodgate 등 실제 구성에 맞춰 초기 수치를 검증해야 합니다.

## L3/L4 및 프로토콜 방어 범위

이 플러그인은 회선 포화를 해소하거나 SYN/UDP 공격을 네트워크에서 차단하는 제품이 아닙니다. **L3/L4는 호스팅사 또는 외부 DDoS 방어망이 필요합니다.** Java Edition용 TCP 방어 경로와 백엔드 접근 제한을 별도로 구성하세요.

ProtocolLib를 설치해도 이미 수신·프레임 디코딩된 패킷을 검사합니다. 압축 폭탄, 비정상 프레임, 서버 코어 취약점을 디코딩 전에 차단한다고 보장하지 않습니다. 최신 보안 패치가 반영된 서버·프록시의 기본 패킷 검증을 함께 사용해야 합니다.

여기서 세션 방어는 **LOGIN START 이후**의 미완료 로그인 추적입니다. 핸드셰이크조차 보내지 않는 TCP 연결과 인증/암호화/압축의 선행 처리 비용은 범위 밖입니다. Paper 단독 모드의 AsyncPlayerPreLogin은 인증 이전 방어가 아닙니다.

진행 중 로그인 슬롯은 `PlayerLoginEvent`에서 반환합니다. 인증·입장 허가 이후의 CONFIGURATION/리소스팩 대기는 이 슬롯 제한에 포함하지 않습니다. 종료된 연결도 주기적으로 정리하며, 로그인 거절은 안내 패킷을 먼저 전송하고 연결을 닫습니다.

서버 자체의 `connection-throttle`, Paper 패킷 제한, 외부 프록시 정책도 별도로 적용됩니다. 이 플러그인이 IP 제한을 사용하지 않아도 다른 계층의 정책이 PC방 같은 공유 IP를 제한할 수 있습니다.

## 명령어

권한: `ddosguard.admin` (기본 OP/콘솔). 일반 유저는 상태나 설정을 변경할 수 없습니다. 별칭은 `/dg`입니다.

| 명령어 | 설명 |
|---|---|
| `/ddosguard status` | 모드, 방어 범위, 누적 통계, 진행 중 로그인 수 |
| `/ddosguard recent` | 최근 접속 거절·추방 요청 10건. 영구 저장하지 않음 |
| `/ddosguard mode observe` | 통계만 기록 |
| `/ddosguard mode enforce` | 제한·추방 적용 |
| `/ddosguard mode off` | 검사 중지 |
| `/ddosguard reload` | 파일 검증 후 설정 적용 |

`mode` 명령은 현재 실행 중인 모드만 바꿉니다. 재시작/reload 후에도 유지하려면 `config.yml`의 `mode`도 수정하세요. 상태 통계는 reload/restart 시 초기화되며, `추방 요청`은 다른 플러그인이 취소할 수도 있는 추방 API 호출 횟수입니다.

## 빌드 및 검증

JDK 17 이상과 Maven 3.9 이상:

```sh
mvn -B -ntp clean verify
```

결과: `target/DDoSGuard-1.0.0.jar`. Paper API 1.20.1과 ProtocolLib API 5.3.0에 대해 컴파일합니다. 외부 의존 라이브러리를 JAR에 묶지 않습니다.

JUnit으로 토큰 버킷, 동시 요청, 로그인 상한/만료, 공유 IP 분리, 위반 유예, 자동 회복, 설정 검증을 검사합니다. MockBukkit으로 플러그인 로딩, 이벤트 취소, 관찰 모드, 권한, 설정 재적용, 로그인 안내를 검사합니다. 실제 실행 결과와 한계는 [검증 보고서](VALIDATION.md)에 기록합니다.
